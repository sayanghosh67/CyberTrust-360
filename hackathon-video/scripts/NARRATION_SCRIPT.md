## Scene 1: 0–20 seconds
A suspicious link. An urgent message. A decision that can put your digital life at risk.

Introducing CyberTrust 360, built by TECHNIX PRO. Your digital world, protected from every angle.

## Scene 2: 20–45 seconds
A familiar logo can hide a phishing website. A fake bank message can turn urgency into a request for your credentials.

UPI scams exploit confusion about payments. Social engineering pushes people to act before checking.

And when evidence changes later, investigators need a way to detect it.

## Scene 3: 45–65 seconds
CyberTrust 360 brings four capabilities into one interface: URL investigation, Scam DNA, relationship intelligence, and blockchain verification.

This is the working application with synthetic demonstration records. Its indicator counter also includes built-in fixtures, a limitation identified in the audit.

## Scene 4: 65–95 seconds
We submit example dot com, a safe demonstration target, through the actual application.

The backend checks DNS, the TLS certificate, HTTP headers, and configured intelligence sources. This run returned a low-risk classification with visible technical evidence.

URLhaus was unavailable, and keyed providers were not configured. These are not successful provider verdicts.

Low risk is not a guarantee of safety. An unavailable check is not proof of malicious behavior.

## Scene 5: 95–125 seconds
Next, we submit a clearly synthetic bank KYC message. It threatens account suspension and asks for an OTP.

Scam DNA identifies manipulation tactics and extracts the indicators. No live language model is configured, so this result comes from deterministic rules.

If money has been transferred, the guidance directs users to their bank or payment provider, helpline 1930, and cybercrime dot gov dot in. Recovery is never guaranteed.

## Scene 6: 125–150 seconds
The relationship graph connects reports and the indicators they share. These demonstration reports reference the same example domain.

Solid green links represent exact shared indicators. Dashed amber links represent inferred similarities such as tactics or brands.

The evidence panel explains each relationship. A shared indicator does not prove that two incidents have the same attacker.

## Scene 7: 150–190 seconds
The Trust Center computes a SHA-256 fingerprint from selected report fields and submits a real registration transaction.

This demonstration runs on a local Hardhat EVM, chain I D 31337. It is a resettable local network, not a public decentralized blockchain.

The receipt confirms registration. Verification compares the recomputed fingerprint with the recorded hash.

Now the built-in demonstration changes the score in memory. The hashes differ, and the interface displays a mismatch.

This proves the demonstrated score-change check. The audit found that some report evidence fields are not yet protected by the hash.

## Scene 8: 190–210 seconds
React connects to FastAPI services for investigation, intelligence, and database persistence. The backend submits selected report fingerprints to the Solidity registry.

Independent verification passed all 58 existing tests and the frontend build. Security and integrity findings still require correction before public deployment.
